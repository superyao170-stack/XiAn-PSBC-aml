## 后续建议

### P0：上线前必须处理

1. 为远程服务器增加 SSH 或 CI/CD 发布通道，并明确回滚、备份和发布责任人。
2. 更换环境文件中出现过的外部 API 密钥、JWT 密钥和默认数据库密码；密钥不要继续放在仓库或镜像层。
3. 生产环境启用 HTTPS；同时限制 Swagger、数据库、图数据库和模型服务端口的公网暴露。
4. 关闭生产环境 MyBatis 标准输出 SQL 日志，避免敏感参数泄露和 IO 压力。

### P1：建议近期完成

1. 为登录、审计、案件详情和导出接口增加限流、失败告警和细粒度权限校验。
2. 对列表接口做 DTO 投影：列表不要默认返回完整长报告，详情页再按需加载。
3. 为大列表、图谱和导出增加分页上限、超时、异步任务状态和取消能力。
4. 增加统一请求 ID、用户 ID、耗时、状态码和 trace ID，串联前后端日志。
5. 为审计日志增加日期范围、IP、操作类型和受控导出；导出应带权限和水印。
6. 为备份、恢复和数据留存建立可验证流程，并定期做恢复演练。

### P2：体验和性能优化

1. 首屏按路由拆包，图谱、报表和大表格组件延迟加载，持续监控首屏体积和接口 P95。
2. 表格统一空状态、加载状态、错误重试和移动端横向滚动策略。
3. 图谱交互增加节点数量保护、渐进加载、筛选条件回显和键盘可访问性。
4. 增加系统版本、构建时间、运行环境和依赖服务状态展示。
5. 增加前端错误监控、接口失败率、慢请求和浏览器兼容性统计。

## 部署建议

推荐使用“前端静态文件 + Nginx 反代 + 后端容器 + PostgreSQL”。发布时先上传到独立目录，做健康检查和核心接口检查，确认后切换软链接；失败则切回上一版本。

本地发布包位于 `artifacts/bankgraph-public-release.tar.gz`。由于当前没有远程登录权限，本次未向 `47.103.137.125` 上传或重启服务。

## 重点风险

- 公网当前为 HTTP，令牌和业务数据存在被窃听风险。
- 公网数据接口可用，生产入口需要确认访问控制、数据脱敏和备份策略。
- SPA 兜底会掩盖 404；本轮 Nginx 已对健康接口和 assets 做更明确的路由处理。
- 发布包包含 workers 目录，应检查是否把 Python 虚拟环境、缓存和测试产物一起打包，以免包体过大或泄露不必要文件。
- 前端依赖审计报告有 8 个漏洞（3 个 moderate、5 个 high），应在上线前逐项确认并升级；不要直接在生产分支使用 `npm audit fix --force`。
- 前端仍有约 1MB 的大 JS chunk，首屏和概览页建议继续拆包。
